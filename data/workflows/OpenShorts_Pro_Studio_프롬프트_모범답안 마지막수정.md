## 2. 막히는 지점 (이 틀이 푸는 문제)

이미지 생성 프롬프트에서 실제로 어려운 것은 두 가지다.

1. **동일화** — 인물·장소·의상이 컷마다 안 바뀌게
2. **현실적 배경** — 일반 “건물/거리”가 아니라 소설 속 그 장소처럼 보이게

원인은 모델이 매 생성마다 “그럴듯한 새 장면”을 그린다는 점이다.  
프롬프트에 **변하지 말아야 할 것**이 짧거나 추상적이면 나머지를 채워 버리면서 얼굴·건물·옷이 바뀐다.

| 약한 프롬프트 | 결과 |
|---------------|------|
| `한국 남자, 국회의사당 앞` | 매번 다른 얼굴, 다른 의사당 |
| `어두운 아지트` | 매번 다른 창고·지하실 |

동일화 = **매 컷 같은 고정 문장 + 같은 참조 이미지**를 강제로 넣는 것이다.

## 3. 에셋 바이블의 역할

바이블은 예쁜 에셋 창고가 아니다.  
**프롬프트 일반화 방지 장치**다.

### 3.1 인물 vs 랜드마크 — 역할이 다르다

| | 인물 | 랜드마크 |
|--|------|----------|
| 소설 | 설정이 **이미 있음** | 지명·분위기만 있는 경우가 많음 |
| 모델 | 이름·성격만 주면 매번 다른 얼굴 | 지명만 주면 **평균 건물**로 뭉갬 |
| 바이블이 할 일 | 소설 설정을 **보이는 특징**으로 추출·고정 | 모델이 모르는 **구조·재료·고유 디테일**을 사전에 박아 둠 |
| 하지 말 일 | 성격을 다시 창작하거나 평가어로 대체 | 지명만 넣고 DNA를 AI가 다시 쓰게 두기 |

### 3.2 고정층 / 가변층

```text
주요 인물·랜드마크 → 사전 등록 DNA 로드
일회성 장소         → 콘티에서 즉석 확보 (업로드 / 생성 / 검색)
        ↓
동적 연출 믹서 (카메라 / 시간·날씨 / 조명)
        ↓
차별화된 시네마틱 프롬프트
```

- **고정층**: 인물·장소 고유 디테일 → 일반화 방지. **글자 단위로 동일 복사**
- **가변층**: 앵글·날씨·조명·표정·의상 → 반복 이미지 방지

일회성 장소(휴게소 화장실, 빗길 골목)도 한 번 잘 나오면 **그 챕터 안에서는** 임시 DNA로 재사용한다.

### 3.3 에셋 확보 2-Track

| 트랙 | 용도 |
|------|------|
| 웹 검색 / 업로드 | 실사 고증 (실제 관공서, 도로, 차량 등) |
| AI로 새 생성 | 오리지널 창작 공간·인물 턴어라운드 |

참조 이미지가 있으면 **비전(Image-to-Prompt)** 으로 정밀 문장화한 뒤, 소설 대본과 합친다.  
배경·의상·포즈 모두 이 경로를 쓸 수 있다. 비전 출력은 초안이고, **잠금 DNA로 채택한 문장만** 바이블에 저장한다.

## 4. 인물 프롬프트 모범

### 4.1 소설 설정을 네 층으로 분리

| 층 | 소설에서 가져올 것 | 프롬프트 역할 |
|----|-------------------|---------------|
| **불변 DNA** | 나이대, 인상, 체형, 얼굴 특징, 흉터·점·안경 등 | 매 컷 **동일 문장** 고정 |
| **가변 상태** | 표정, 상처, 땀, 피로, 화장 | 컷마다만 변경 |
| **의상** | 평소 옷 / 씬 의상 | 인물 DNA와 **분리** (옷장 슬롯) |
| **연출** | 카메라, 조명, 구도 | DNA 밖 |

소설 문장(성격, 대사 버릇, 과거)을 통째로 넣지 않는다.  
**카메라에 보이는 것만** 추출해 한 블록으로 고정한다.

예: 소설의 “냉정한 검사” → `얇은 입술, 낮은 미간, 시선이 카메라 밖`

### 4.2 인물 고정 블록 템플릿

사람마다 **한 번만** 만들어 바이블에 저장하고, 생성 시 복사만 한다.

```text
[IDENTITY — 이름/코드]
{연령대} {한국인/동양인 등} {성별},
{체형·키 인상 한 줄},
{얼굴형}, {눈·눈썹}, {코·입 특징},
{머리 길이·스타일·색},
{고정 식별점 1~3개: 점, 흉터, 안경, 수염 등}
```

**규칙**

- `잘생긴`, `예쁜`, `카리스마` 등 **평가어 금지**
- **식별 가능한 구체 특징** 2~4개 이상
- 소설에 있는 흉터·점·안경 등은 반드시 포함
- 이 블록은 컷마다 **글자 단위로 동일** (다시 서술하지 않음)
- 이름만 넣지 않는다. 이름 없는 DNA 문장이 본문

### 4.3 의상은 인물과 분리

```text
인물 DNA + 이번 씬 의상 프리셋
예: 검은 정장, 넥타이 풀림, 젖은 어깨
```

같은 얼굴·다른 옷을 유지하려면 의상을 DNA에 섞지 않는다.

### 4.4 인물 동일화 규칙

1. 한 사람 = **한 고정 문자열**
2. 의상·표정·배경만 변수
3. 얼굴 참조 이미지가 있으면 슬롯에 넣고, 텍스트 DNA는 보조
4. 잘 나온 컷의 얼굴은 그 인물의 **ref로 승격**
5. Qwen 멀티샷 기준으로 정면 등 사전 준비를 권장 (설계 인물 슬롯)

## 5. 배경·랜드마크 모범

모델은 “국회의사당”, “아지트”의 **그 소설 버전**을 모른다.  
지명만 넣으면 학습 데이터의 평균 이미지로 간다.

### 5.1 잠금 DNA

바이블에 **그 장소만의 문장**을 정해 매 컷 동일하게 넣는다.

```text
(잠금 DNA 형태)
대한민국 국회의사당, 청동빛 중앙 돔, 정면 높은 계단,
양옆 세로 기둥 열, 밝은 화강암 외벽, 넓은 앞광장
```

그 위에만 이번 컷 연출을 올린다.

```text
+ 비 오는 밤, 바닥 반사, 로우앵글, 가로등 빛
```

### 5.2 현실감을 올리는 요소

| 요소 | 예시 |
|------|------|
| 구조 | 돔, 기둥 수, 계단, 광장 축선 |
| 재료 | 화강암, 젖은 아스팔트, 녹슨 철문, 형광등 |
| 생활 흔적 | 쓰레기통, 전선, 표지판, 물때, 먼 차량 |
| 공기 | 안개, 비 줄기, 한낮 강한 그림자, 실내 먼지 |
| 스케일 | 사람 대비 계단·기둥 크기 |

“아름다운 건물”보다 **재료 + 구조 + 생활 흔적 + 빛**이 실사에 가깝다.

### 5.3 DNA 권장 형태 (텍스트만으로 부족할 때)

- **잠금 문구** — 반드시 들어갈 디테일 (복사 전용)
- **참조 이미지** 1~3장 — 원경 / 입구 / 내부
- **금지 표현** — 이 장소가 되면 안 되는 것
- 비전 Image-to-Prompt 초안은 여기 넣고, 채택 문장만 잠금

### 5.4 동적 연출 믹서 (고정 DNA 위에만 올린다)

단순 복사만 하면 컷이 반복된다. DNA는 고정, 연출만 바꾼다.

| 축 | 보기 |
|----|------|
| 카메라 | 드론 원경 / 로우앵글 / 오버더숄더 / 클로즈업 |
| 시간·날씨 | 자정 폭우 / 노을 / 한낮 / 안개 |
| 조명·색감 | 깜빡이는 형광등 / 네온사인 반사 / 가로등 바닥 반사 |

## 6. 한 컷 프롬프트 조립 순서 (모범)

```text
[1] IDENTITY 고정 블록          ← 바이블 (수정 금지)
[2] 이번 컷 의상 프리셋         ← 옷장
[3] 이번 컷 상태 (표정·땀·상처) ← 대본 지문만
[4] 동작·포즈                   ← 대본
[5] 배경 잠금 DNA               ← 랜드마크 바이블
[6] 카메라·조명·날씨            ← 연출 믹서
[7] 실사 스타일 고정 문구       ← 공통
```

잠금 DNA를 **앞**에 둔다.  
AI가 대본만 보고 인물·배경을 새로 쓰지 않게 한다.

### 한 줄 모범

> 소설 설정 → **불변 DNA 한 블록 고정** →  
> 매 컷 `DNA + 의상 + 이번 상태 + 동작 + 배경 DNA + 연출`  
> 평가어·추상어 금지. 식별 디테일·참조 이미지로 동일화.

## 7. 이미지 파이프라인과의 연결

### 7.1 한 컷 이미지 완료 정의

1. 위 순서로 프롬프트 조립 + (있으면) 참조 슬롯 매핑
2. 최소 1엔진으로 후보 생성 (기본: Z-Image Turbo)
3. 필요 시 **이 컷 3엔진 비교** (순차 큐)
4. 슬라이더로 후보 선택
5. 부위 수정이 필요하면 I2I / Qwen Image Edit (얼굴 보존 + 의상·배경 교체)
6. `winner.png` 확정 + 시트에 모델·시드·최종 프롬프트·참조 기록

일반화 방지는 **이미지 확정 시점**이 승부처다.  
영상은 `winner.png`를 따르므로, 바이블은 스토리보드(2D)에서 이미 먹어야 한다.

### 7.2 엔진 선택 가이드 (프롬프트 이후)

| 엔진 | 이 컷에 쓸 때 |
|------|----------------|
| Z-Image Turbo | 빠른 초안, 동양인 인물, 실내·로맨스 조명 |
| Krea 2 Turbo | 피부 질감, 시네마틱 심도, 액션 포즈 |
| Qwen Image 2512 | 한국 배경, 간판·관공서, 지문 고증 |

한 엔진이 전부 해결하지 않는다.  
배경 고증 컷 → Qwen 비중, 얼굴 고정 컷 → **참조 + 잠금 DNA** 강화.

### 7.3 9슬롯과 프롬프트 태그 (필수 불변식)

슬롯 **라벨**은 고정이다. **슬롯 번호 ≠ H3 `<Picture N>`.**

```text
1 배경 공간
2 메인 인물 얼굴
3 서브/상대 인물
4 의상/착장
5 동작/포즈
6 핵심 소품 1
7 차량/탈것
8 보조 소품 2
9 특수 스타일/무드
```

| 모드 | 슬롯이 되는 것 |
|------|----------------|
| 2D 엔진 | 빈 슬롯 압축 → 핀 0,1,2… 와 `<Picture 1~K>`를 **같이** 재번호 |
| H3 I2VA | `<Picture 1>` = `winner.png` (0.00초 첫 프레임). 9슬롯 Picture 직결 금지 |
| H3 FL2VA | Picture 1 = 시작 프레임, Picture 2 = 끝 프레임 |
| H3 Full-Ref | 슬롯 역할 이미지 = `<Subject N>`. Picture는 프레임·콘티 앵커만 |

상세 매핑·하지 말 것·저장 키는 `OpenShorts_Pro_Studio_9슬롯_매핑.md`.

### 7.4 시트에 남길 프롬프트 관련 필드

컷 ID, 원문, 대사, **최종 조립 프롬프트**, 시드, 엔진, 참조 슬롯(라벨 키), 사용한 인물 DNA ID, 랜드마크 DNA ID, 의상 프리셋 ID.
