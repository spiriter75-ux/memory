# 지피로지스 관제 시스템(Control Center) 모바일 반응형 개편 계획서

현재는 확약서를 안정적으로 수집하는 것이 최우선이므로 서비스에 영향을 주지 않도록 운영 환경을 유지하고 있습니다. 본 계획서는 추후 시간이 확보되었을 때, 기존 데스크탑(PC) 환경의 사용성을 전혀 훼손하지 않으면서 모바일(휴대폰)에서도 데이터를 깔끔하게 조회하고 관리할 수 있도록 시스템을 개편하기 위한 방안입니다.

## 1. 개편 목표 (Goal)

1. **안정성 최우선**: 기존 PC 브라우저에서의 넓은 화면 레이아웃과 기능(배차 관리, 현장 관리 등)이 100% 동일하게 동작하도록 유지합니다.
2. **모바일 가독성 확보**: 좁은 모바일 화면에서 테이블이 깨지거나 버튼이 겹치는 현상(개판으로 보이는 현상)을 완벽하게 해결합니다.
3. **터치 친화적 UI**: 휴대폰에서 조작하기 쉽도록 햄버거 메뉴(사이드바 숨김/펼침)를 도입하고 모달(팝업) 창을 모바일 화면에 꽉 차게 최적화합니다.

## 2. 주요 문제점 및 개선 방안 (Proposed Changes)

모바일 화면에서 UI가 망가졌던 핵심 원인 3가지를 분석하고, 다음과 같이 개선할 계획입니다.

### 2.1 사이드바(메뉴) 및 전체 레이아웃
- **문제점**: 좌측 메뉴바가 모바일에서도 고정된 너비(288px)를 차지하여 실제 데이터(오른쪽 화면)를 볼 공간이 부족했습니다.
- **개선 방안**:
  - PC 화면: 기존과 동일하게 좌측 고정 메뉴 사용
  - 모바일 화면: 메뉴를 기본적으로 숨기고, 상단에 **'☰ (햄버거 버튼)'**을 추가하여 누를 때만 메뉴가 스르륵 나타나는 오프캔버스(Off-canvas) 또는 드롭다운 형태로 변경합니다.

### 2.2 데이터 테이블 (배차 목록, 운행일지 등)
- **문제점**: 열(Column)이 많은 테이블이 모바일의 좁은 가로 폭에 억지로 맞춰지면서 글자가 겹치거나 세로로 길게 늘어지는 현상이 발생했습니다.
- **개선 방안**:
  - `overflow-x-auto` 속성을 부여하여 좁은 화면에서는 테이블이 찌그러지지 않고 **좌우로 스와이프(스크롤)**하여 볼 수 있도록 구조를 변경합니다.
  - 모바일에서는 덜 중요한 정보(예: 해시코드, 일부 날짜/시간 초 단위)를 숨기거나(카드 형태로 변환), 최소 가로 너비(`min-w-[700px]` 등)를 보장하여 데이터 가독성을 지킵니다.

### 2.3 모달 창 (입력 및 수정 팝업)
- **문제점**: 모달이 모바일 화면 너비보다 크거나 여백이 적절치 않아 일부 버튼이 화면 밖으로 벗어나는 경우가 있었습니다.
- **개선 방안**:
  - 모바일에서는 모달 창을 화면에 꽉 차게(`w-full`, `max-h-[90vh]`) 띄우고, 내부에 스크롤을 적용하여 모든 입력 폼과 저장 버튼에 쉽게 접근할 수 있게 합니다.

## 3. 작업 진행 컴포넌트

### [MODIFY] `c:\스마트GP 배차시스템 확약서\deploy\public\control.html`

- **레이아웃 구조 변경**: `<aside>` (메뉴) 및 `<main>` (본문) 영역에 Tailwind CSS의 반응형 유틸리티(`md:flex`, `hidden md:block` 등)를 적용.
- **햄버거 메뉴 추가**: 모바일 상단 헤더 영역 신설 및 메뉴 토글 버튼 구현.
- **테이블 스크롤 컨테이너 래핑**: 모든 `<table>` 태그 바깥에 `<div class="overflow-x-auto">` 래퍼(Wrapper) 추가.
- **반응형 폰트 및 여백 적용**: 좁은 화면에서는 폰트 사이즈와 패딩(Padding)을 유동적으로 축소(`p-4 md:p-8`, `text-sm md:text-base` 등).

## 4. Verification Plan (검증 계획)

> [!TIP]
> 작업이 완료된 후에는 운영 환경에 바로 덮어쓰지 않고, 안전하게 테스트를 진행할 예정입니다.

### 4.1 크로스 브라우저 및 디바이스 테스트
1. 개발 환경 브라우저 개발자 도구(F12)를 통해 iPhone SE, iPhone 14 Pro, Galaxy S20 등 다양한 해상도 시뮬레이션 테스트
2. PC 환경에서 창 크기를 줄였다 늘렸다 하며 레이아웃 깨짐(Breakpoint) 검증

### 4.2 실제 기기 테스트 요청 (Manual Verification)
코드 수정 후 로컬 테스트가 통과되면, Firebase Hosting에 배포한 뒤 관리자님께 휴대폰(Safari, Chrome)으로 직접 접속하여 다음 항목들을 점검해 주시기를 요청드릴 계획입니다.
- 메뉴 토글(열기/닫기) 정상 작동 여부
- 배차 목록 등 테이블 우측 스크롤 작동 여부
- 모달 창에서 내용 입력 및 저장 버튼 클릭 가능 여부
